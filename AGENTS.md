# Notes for AI agents and contributors

Read `docs/ARCHITECTURE.md` (module map) and `docs/THEORY.md` (model and conventions) before
changing physics or geometry.

## Commands

```sh
deno task check      # lint + format check + unit tests — must pass before every commit (CI runs it)
deno task test       # unit tests only
deno fmt             # format (lineWidth 100)
deno task serve      # http://127.0.0.1:8000/
deno task smoke      # headless Chrome end-to-end check + screenshots/ (needs `deno task serve`)
```

There is no build step and no Node. Browser dependencies come from the import map in `index.html`.

## Invariants

- **`src/core/` stays pure.** No DOM, no three.js, no globals. It is SI units throughout, and every
  change there needs a unit test. The core is deterministic for given parameters.
- **Conventions are fixed:**
  - convex-positive curvatures;
  - outward normal $n=S_\theta\times S_z/|\cdot|$;
  - braid angle measured from the meridian;
  - Darboux $b=n\times t$;
  - $\omega$ is the carrier revolution rate.
    The "Conventions" block is identical in `src/core/surface.js` and `docs/THEORY.md` §1. Keep them
    in sync.
- **Naming.** Use `g_zz, g_tt, ii_zz, ii_tt` (never E, F, G, L, M, N) for fundamental forms. `G` is
  the guide point, `L` the free length, `N` the carrier count.
- **Views never mutate the Simulation.** Parameters live in `params` (UI units, `src/params.js`);
  display-only settings live in `app.display`.
- **Interlacing validity.** Pattern $m/m$ needs $2m \mid N$ (validated in `params.js`, asserted in
  `CircularBraider`).
- **Colour.** Colours come from `src/view/colormaps.js`, whose categorical slots are validated for
  colour-vision deficiency. Keep "color follows the entity": "+" orange, "−" aqua, quasi-static blue,
  geodesic yellow. Keep status colours for status only, and never add unlabelled colour encodings.
- **Physics changes must be documented and validated.**
  1. Update `docs/THEORY.md` and the Theory panel (`src/ui/theoryPanel.js`).
  2. Keep or extend the validation tests: analytic cylinder solution, Du–Popper transient, SciPy
     fixture, closed forms vs finite differences.
- **No unverified claims in user-facing text** (About tab, README, Theory). Check a new claim
  numerically with the core before writing it, and verify new references (e.g. via Crossref).

## Files

- Every source file starts with a header comment: purpose, inputs and outputs, conventions.
- Exported functions carry JSDoc with units.
- `screenshots/` and `_site/` are generated and git-ignored.
- `tests/fixtures/taper_scalar_ode.json` is generated by `tests/fixtures/generate_fixtures.py`. Keep
  its `CASE` in sync with `taperError()` in `tests/deposition.test.js`.

## Commits

Small, focused commits with a descriptive subject. `main` deploys automatically to GitHub Pages
after CI passes.
